# 12 — Legacy system reference (`email-approval-app`) — read this instead of the code

Purpose: everything an executor needs to know about the *existing* app in one place, so it can build or migrate without re-reading the legacy repo. Deeper detail, with file paths and line references, lives in `survey/` (db.md, db_domains.md, routes.md, services.md, frontend.md, legacy_data.md). Numbers as of 2026-09-02.

## 1. What it is
Internal operations CRM for OZee Web & Digital (Perth, AU). Laravel 12 / PHP 8.2, Inertia 2, **Vue 3 for ~220 pages + React 19 for 3 page groups** (inbox beta, supplier portal, test page), Tailwind v3 (Vue only), MySQL, database queue drained by cron, Reverb websockets, Sanctum, spatie/activitylog, Pulse. Built ad hoc over a year by several AI agents; **no planning, heavy duplication, many latent bugs** (§9). 485 PHP files in `app/`, 100 models, ~130 controllers, 50 services, 247 migrations, 220 Vue pages, 185 Vue components, 67 React files (~21k lines, high quality).

## 3. Audiences and auth paths (five separate systems)
| Audience | Entry | Mechanism |
|---|---|---|
| Staff | `/login` → OTP (`user_otps`, 6-digit, mail sent sync) → session; per-device remember cookie (`user_remembered_devices`, sha256, 30d) | `web` guard; `EnsureNotGuest` logs out `user_type=guest` |
| Clients | `/client/dashboard/{token}` magic link (`magic_links type=client`) → optional PIN (`clients.pin` **plaintext**, `temporary_pin`) → `/api/client-api/*` with `auth.magiclink` | `VerifyMagicLinkToken` rejects any used token (friction) |
| Suppliers/guests | `/projects/public/{slug}/{code}` (project `public_share_token`, first 12 chars in URL) → OTP (`otp_verifications`) → HttpOnly `portal_session` cookie (`PortalSessionService`, not the web guard) → `/portal/*` React | `EnsurePortalUser`; guests are `users.user_type=guest` |
| Chrome extension / desktop tracker | `X-API-KEY` = `users.api_key` (`auth.apikey`) | `/api/activityData`, `/api/activity/*`, vault resolve |
| Third-party apps | `X-Magic-Token` (`magic_links type=external`, whitelist, max_uses) | `/api/external/email/send`, payments |
| Webhooks | Telegram, Xero (HMAC), Stripe, public lead intake, FamifyHub, bugs | mostly unauthenticated |

Permissions: `roles` (slug, type application|client|project) ↔ `permissions` (slug, category) via `role_permission`; `users.role_id` global; `project_user.role_id` per project. Checked by middleware `permission:{slug}` (super-admin bypass; project scope if route has `project`, **falls back to global**), `permissionInAnyProject`, 9 policies (`User::hasPermission` only looks at the global role), and scattered `isManager()` checks. Seeded by 7 seeders + 2 migrations; ~100 slugs; `manage_projects` overloaded (gates leads, campaigns, automation, reports…). Frontend re-fetches `/api/user/permissions` after mount (shared-props version is commented out). Known holes: `roles.index?type=` bypass; several admin/finance routes with no permission; users pages gated by `create_users`.

## 4. Data model by domain (what each table is *for*; full columns in `survey/db_domains.md`)
**Identity:** `users` (staff+contractors+guests; `user_type`; JSON `metadata` (supplier profile + encrypted payout methods), `notes`, `checklist`; `api_key`; Telegram/Xero columns; global scope orders by name, global `$with=[role,categories]`), `roles`, `permissions`, `role_permission`, `user_remembered_devices`, `user_otps`, `otp_verifications`, `login_attempts`, `magic_links` (two subtypes), `google_accounts` (per-user OAuth, unencrypted; the *app* mailbox token is a file `storage/app/private/google_tokens.json`), `telegram_accounts`, `user_metadata_keys`, `user_notes` (encrypted).
**CRM:** `clients` (name/email/phone, `lead_id`, `pin`, Xero contact cols; no casts, no soft delete, hides `email` per row via permission check), `leads` (27 cols: first/last name, company, status enum (11), `pipeline_stage`, source, estimated value, `tags` comma string, `email_thread_history` JSON), `campaigns` (+ inline `email_template` longText, `ai_persona`), `campaign_shareable_resource`, `contexts` (two morph pairs: referencable email/note/task ↔ linkable client/lead/user), `client_vault_credentials` (uuid PK, per-row salt, PIN-derived encryption) + `_user` shares.
**Projects:** `projects` (client_id, status enum ≠ PHP enum, payment_type, `services`/`service_details`/`documents`/`data`/`integrations` JSON, manager/admin ids, telegram/google chat cols, `public_share_token`, tier, hidden `profit_margin_percentage` recomputed by observer), `project_user` (role_id), `project_client` (role string + role_id), `project_tiers` (PKR columns), `crm_services` (catalogue), `project_services` (+ `payment_breakdown` JSON = payment milestones; enquiry_* mirror), `project_deliverables` (= scope checklist), `project_expendables` (**budget when `user_id` NULL, contractor proposal/contract when set**; morph Project|Milestone; status Title Case), `resources` (links/files), `documents`, `seo_reports` (json blob per month), `meetings` (+attendees; Google Calendar mirror), `wireframes`/`wireframe_versions`.
**Work:** `milestones` (status DB enum `Not Started/In Progress/Completed/Overdue` vs PHP enum with 10 lowercase cases — bridged by a synonym cast; five lifecycle dates; magic `support` milestone), `tasks` (**no project_id** — via milestone; status enum lacks `Paused` which code writes; `parent_id`; `creator` morph user|client; `source/source_id` pseudo-morph; `effort`, `manual_effort_override` secs; `$appends total_time_spent` replays `activity_log`), `subtasks` (second hierarchy), `task_types` (no unique, no seeder → fresh install can't create a task), `daily_tasks` (per-user day plan), `schedules` (polymorphic cron; reverse relations broken by camelCase morph name).
**Email:** `conversations` (subject, `conversable` client|lead, project_id nullable, `contractor_id` owner, ai_summary_*), `emails` (`conversation_id`, `sender` morph, `to` varchar(255) cast array, `body` in **five shapes** (plain text / markdown / HTML / blocks HTML with cid / NULL when templated; plus AI JSON `{greeting,paragraphs,cta}`), `status` 13 values, `type` received|sent (historical rows mis-stamped), `message_id` (Gmail API id) vs `rfc_message_id`, `gmail_thread_id`, `in_reply_to_email_id`, `template_id` + `email_template` slug, `template_data` **double-encoded JSON holding placeholders ∪ blocks ∪ inbound headers**, `draft_meta`, `is_private`, ai_status/ai_reason/ai_draft*, `read_at`, soft delete = bin), `email_templates` (+ `placeholder_definitions` via pivot; placeholders regex-extracted from body), `email_apps` (SMTP/API mailboxes for the external send API), `external_email_logs`, `user_interactions` (opens/reads).
**Automation:** `workflows` (trigger_event string), `workflow_steps` (tree at `step_config->_parent_id`, branches at `->_branch`, 14 step types), `execution_logs` (per step, JSON context/output, no timestamps), `prompts` (versioned; steps pin a version). Workflow **17** = the email approval gate (AI check → send or park at pending_approval).
**Finance:** `transactions` (**five purposes**: income, expense, bonus, invoice payment (`invoice_id`), bill payment (`bill_id`); `currency` lowercase default; `exchange_rate` late addition; observer recomputes project margin on every write), `transaction_types`, `invoices` (client, project, total not derived, `invoice_number` column shadowed by accessor `OZI{id}`, `xero_payment_service_ids` JSON array), `invoice_items` (`milestone_key` → JSON path in `project_services.payment_breakdown`; uniqueness deliberately dropped), `invoice_comments` (comment + audit actions), `bills` (contractor, project, expendable, status enum, Xero cols), `bill_payment_details` (encrypted bank details per bill), `approval_flows/_steps/_instances/_instance_steps` (used by bills only), `currency_rates` (no history), `xero_connections` (single row, encrypted tokens) + `xero_tenants` + `xero_payment_services` + `airwallex_xero_bank_mappings`, `stripe_configurations` (per external app) + `stripe_subscriptions` + `_payments` (int minor units, string joins) + `stripe_payouts` (string PK, `breakdown` JSON).
**Recognition:** `points_ledgers` (morph pointable incl. table-less `WeeklyStreak`; denial rows with reason), `kudos`, `bonus_configurations` (camelCase columns) + groups + items + `project_bonus_configuration_group`, `bonus_transactions`, `monthly_budgets` (PKR), `monthly_points`.
**Presence:** `user_availabilities` (per-date, three reason FKs into `categories` with no seeder), `user_activities` (browser telemetry, ≥387k rows, ~700/day), `user_productivities` (snapshots, `ai_report_json` not always valid JSON).
**Chat:** `chat_messages` (internal + Telegram; user_id/client_id), `telegram_topics` (forum topic per project, typed), `project_google_chat_members`; Google Chat ids as strings on projects/tasks/notes.
**Content:** `presentations` (morph presentable lead|client, share_token) → `slides` → `content_blocks` (13 JSON shapes), `presentation_metadata` (EAV), `presentation_user`, `components`/`icons` (from config), `shareable_resources` (+ `NoticeBoard` model on the same table via `notice` boolean).
**Cross-cutting:** `project_notes` (**nine things**: note, standup, kudos, task/milestone/deliverable/document comment, user note, wireframe annotation; encrypted content; `creator` morph + dead `user_id`; enum stores 3 of 7 written types), `comments` (generic morph, barely used), `files` (model `FileAttachment`; morph + denormalised project_id; GCS path or URL or Drive id), `tags`/`taggables`/`task_tag`(dead), `category_sets`/`category_set_bindings`/`categories`/`categorizables`, `notifications` (data as text), `activity_log` (application state: task durations), `deliverables` (client approval artefact; hand-rolled approval) + `client_deliverable_interactions` + dead `deliverable_comments`.
Polymorphism: 21 morph names, only Task/Workflow/Email aliased (three spellings each in data), 9 hand-rolled pseudo-morphs. ~62 JSON columns. ~44 free-string status columns vs 13 enums. Four PK strategies.

## 6. Key flows (behaviour to preserve)
- **Gmail ingestion**: `emails:fetch` every minute polls `is:inbox after:{watermark-5min}`; dedupe by Gmail id; sender email → client (with project → conversation status draft) / lead / unknown (`Unknown`, project NULL, matched on subject only); body cleaned to plain text; attachments to GCS with thumbnails. `inbox:fetch-sent` (5 min) ingests mail sent from the Gmail UI (OURS/THEIRS/SEEN by rfc id / thread id). **No push/pubsub.**
- **Sending**: block emails rendered before layout wrap; attachments from GCS; branded Blade layout; a fresh RFC Message-ID minted per send; reply → In-Reply-To/References + quoted thread appended (**not stored**); one Gmail send per recipient, only first recipient's ids recorded; single atomic update to `sent`.
- **Approval gate**: email created as `draft` → Eloquent wildcard event → workflow 17 → AI "Email Approval Analysis" → send (`ACTION_PROCESS_EMAIL`) or `pending_approval` → human approve / edit-and-approve / reject (reason ≥10). Beta inbox rule: automation owns a draft for `inbox.manual_approval_after_minutes` (30). Invariant `guardStatusRegression`: sent never goes back. `can_approve` = `approve_all_emails` | project `approve_emails` | `approve_received_emails` | `contact_lead`.
- **Reply clock**: needs-reply = newest inbound newer than newest delivered outbound; SLA `inbox.sla_minutes` (60); cutover `inbox.reply_clock.since`. Private: `is_private` withheld without `view_private_emails`; screening: `pending_approval_received` withheld without `approve_received_emails`; redaction server-side.
- **Tasks**: starting a task pauses the user's other in-progress tasks; block with reason; complete dispatches `TaskCompleted` (points); duration derived from activity_log; Telegram `/task` command creates tasks; client tickets via magic link set `creator` client.
- **Milestones**: mark complete → approve (points to all assignees, fires on every update while approved) / reject / reopen; due-date change logged as note with reason; support milestone auto-created per project.
- **Deliverables**: submit → client sees in dashboard → mark read / approve / request revisions / comment (project_notes); overall approval on the deliverable.
- **Finance**: bill created (staff or supplier upload) → `BillApprovalFlowService` starts flow → approve steps → Xero ACCPAY push → payments recorded as transactions (Airwallex ref) → status recalculated with currency conversion; invoices → Xero ACCREC push, hourly status pull, webhook; contract limit `BillExceedsContractException`; proposals (expendables with user) accept/reject/shortlist/complete; project profit margin recomputed by transaction observer.
- **Supplier portal**: share link → OTP → cookie session → projects shared with you → phases (milestones) → one proposal per phase (multi-phase modal) → bills against accepted proposal → payout methods in `users.metadata` (encrypted) → profile ID details.
- **Points**: standup 25/10, task 50, milestone 500/100, kudos 25, email 50 (never awards — enum bug); weekly streak command; ledger records denials with reasons; monthly budgets convert points to PKR.
- **Scheduler**: `app:run-scheduler` every minute → `schedules` (cron) → Task spawn / Workflow run / Email delayed→draft. Queue drained by cron `queue:work --stop-when-empty` (no supervisor).
