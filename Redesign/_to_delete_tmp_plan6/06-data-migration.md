# 06 — Data migration (legacy MySQL → `ozee-crm-v2`)

Ground truth: `survey/legacy_data.md` (dump of 30 tables, 2026-09-01: ~5.4k core rows; live estimates: tasks ≥15.9k, project_notes ≥13.6k, milestones ≥1.6k, user_activities ≥387k telemetry). Everything except telemetry and mail fits in memory; correctness matters more than speed. **Always run against the live legacy DB via a read-only MySQL user on connection `legacy`.**

## 1. Principles
1. Idempotent, resumable, chunked (`chunkById`), every step writes `migration_map(entity, legacy_id, v2_id, meta JSON)`; re-running skips mapped rows and applies deltas (`updated_at > last_run`).
2. Never transform in the legacy DB. Never write to it.
3. Unknown/invalid legacy values → explicit fallback + a row in `migration_issues(step, legacy_table, legacy_id, issue, payload)`; the run report lists counts per issue. Zero silent drops.
4. Deferred modules → `legacy_*` raw copies (02 §09) — a plain `INSERT … SELECT` over the `legacy` connection per table, done first so nothing is lost even if later steps fail.
5. Secrets: `google_accounts` tokens re-encrypted; Xero tokens re-encrypted; `bill_payment_details.details` decrypted with the legacy APP_KEY (config `legacy.app_key`) and re-encrypted; `clients.pin` plaintext **not** migrated (clients set a new PIN on first Client OS login); `magic_links.temporary_pin` dropped; `users.password` hashes copied as-is (bcrypt compatible).
6. Order = module order (02 §6). Each step has a verification query pair (legacy count vs v2 count) recorded in the report.

## 2. Tooling (ticket D6-02)
`php artisan legacy:migrate {step|all} [--dry-run] [--since=] [--limit=]`, steps registered in `modules/Platform/Migration/Steps/*.php` implementing `MigrationStep { name(); dependsOn(); run(Context); verify(): VerifyResult }`. Helper `Map::get('client', $id)`, `Map::put(...)`. Logging to `storage/logs/migration-{run}.log` + `migration_runs` table.

## 3. Step 0 — Profiling (D6-01)
Run on live: row counts for all tables (`information_schema`), and the distributions listed in `survey/legacy_data.md §2.10` for tables absent from the dump (emails, conversations, files, magic_links, leads, tags/taggables, categories, comments, user_notes, meetings, daily_tasks, notifications, activity_log, xero_*, stripe_*, currency_rates, email_templates, placeholder_definitions, email_apps, external_email_logs, client_vault_credentials). Output `docs/migration/profile-{date}.md`.

## 4. Mapping steps (one ticket each)

### 4.1 identity
- `users` → `users`: `user_type` employee→staff, contractor→contractor, guest/supplier→supplier (NULL→staff); `role_id` via role slug map (`super-admin`→super-admin, `manager`/`assistant-manager`→manager, `employee`, `contractor`; client-* roles → NULL and user flagged issue); `deleted_at` → `is_active=0` (+ keep deleted_at); `extension_mandatory`→`requires_extension`; `metadata` → `user_profiles` (keys per `PortalProfileService::ID_TYPES` and address fields) and `payout_methods` (decrypt `payment_methods`, one row per method, `is_default` from `default` flag); `checklist` JSON → `personal_checklist_items`; `notes` JSON → comments (subject user, kind note, author = super-admin, body = each entry); `api_key` → `api_keys` (store `key_hash=sha256(api_key)`, prefix first 8 — so existing extension installs keep working; document in cutover); `user_remembered_devices` → `remembered_devices` (unexpired only); `google_accounts` → `google_accounts` (re-encrypt; `created+expires_in` → `expires_at`); app `google_tokens.json` → one row `is_app_mailbox=1` on the super-admin. Roles/permissions are **seeded, not migrated**; custom permission grants beyond the seeded matrix → issues list for manual review.
- Verify: users count; every legacy user with a login in last 90 days is active.

### 4.2 taxonomy
- `tags` → `terms(taxonomy=tags)`; `category_sets` → taxonomies (slug from set slug; `applies_to` from bindings' FQCN → morph alias), `categories` → terms; distinct `leads.source`, `projects.source` (+ the hard-coded `sourceOptions`) → `lead_sources`/`project_sources`. `taggables`/`categorizables`/`leads.tags` → `term_assignments` after subjects are mapped (run again at end: step `taxonomy-assign`).

### 4.3 contacts
- Build a unified id space: for each `clients` row → contact stage=client; for each `leads` row: if some client has `lead_id = lead.id` OR same email as a client → **merge** into that client's contact (fill missing fields, keep `converted_at`, pipeline_status=won, map `lead:{id}`→ same v2 id); else → contact stage=lead. `clients.name` split: last token = last_name. `leads.status` map: new→new, hot_incoming/hot_outgoing/processing/contacted/outreach_sent→contacted, qualified→qualified, sequence_completed→dormant, generation_failed→new(+issue), converted→won, lost→lost. `assigned_to_id`→owner; `campaign_id` + `metadata.additional_campaign_ids` → `campaign_contact`; `clients.notes`/`leads.notes` non-empty → comment kind note. `xero_contact_id` → `xero_links(contact, contact)`. Telegram cols → `legacy_telegram_accounts`.
- `campaigns` → `campaigns` (drop template/persona → `legacy_campaign_ai`).
- Verify: contacts = clients + unmerged leads; no duplicate emails.

### 4.4 projects & members
- `projects` → `projects`: status enum copy (`archived`→status archived + archived_at); `payment_type` monthly→retainer; `source`→term; `project_manager_id`/`project_admin_id` → `project_members` with role project-manager (dedupe with `project_user`); `project_user.role_id` → project role slug map (`project-manager|project-member|project-viewer`; unknown → member + issue); `project_client` → `project_contacts` (role_id→primary if role matches client-admin/Primary else viewer; ensure `projects.client_id` row is primary); `preferred_keywords`, `reporting_sites`, `google_drive_folder_id`, `integrations` → `settings` JSON; `logo` → attachment kind logo (copy object from GCS/local `storage/app/public`); `documents` JSON entries + `documents` table → attachments kind document (Drive ids keep `disk=gdrive`); `public_share_token` + `public_share_enabled` → `access_links(kind=project_share, token_hash=sha256(token))` so existing supplier links keep working; `project_tier_id`/`profit_margin_percentage`/telegram/google chat → archive.
- Verify: projects count; every project has exactly one primary contact and ≥1 manager (issue if not).

### 4.5 work
- `task_types` → dedupe by lower(name) → v2 `task_types` (map many→one); `milestones` → `milestones` (project_id NULL → issue + attach to a "Recovered" project? No: skip and log; tasks under it fall to the project support milestone if the task's project can be inferred from `daily_tasks`/notes, else issue). Status map: `Not Started`→planned, `In Progress`→in_progress, `Completed`→ approved_at? completed : (mark_completed_at ? submitted : completed), `Overdue`→in_progress; `completion_date`→due_at; support milestone by name `support` → `is_support=1`.
- `tasks` → `tasks` with `project_id` = milestone.project_id (tasks with NULL milestone_id → issue; assign to first project the assignee is member of only if unambiguous, else "Unassigned" holding project per user? **Decision: create one `Recovered tasks` project per legacy orphan cluster is wrong** — instead put them under a single internal project "Internal / Unfiled" (created in seeder, client = OZee internal contact) and flag). Status map: `To Do`→todo, `In Progress`→in_progress, `Done`→done, `Blocked`→blocked, `Archived`→archived, ''→todo(+issue); `Paused` appears only via activity_log → paused; `priority` copy; `effort` hours→minutes×60; `manual_effort_override` seconds→minutes; `needs_approval|requires_qa`→needs_review; `source`→origin map (local→manual, email→email, client/magic_link→client_portal, wireframe→wireframe, telegram→telegram, workflow→automation); `subtasks` → child tasks (`parent_id`=map(task)), status map same; `project_deliverable_id`→scope_item.
- Time: replay `activity_log` status changes per task (`Task::calculateTotalTimeSpent` semantics: sum of intervals `In Progress`→next status) → `task_time_entries(source=tracker)`; total must equal legacy `total_time_spent` for a 50-task sample (verification).
- `daily_tasks` → `daily_plan_items` (pending→planned, completed→done, pushed_to_next_day→carried_over). `project_deliverables` → `scope_items` (`details` JSON → checklist; status pending/in_progress/completed→delivered). `deliverables` → `deliverables` (type/mime_type → DeliverableType: video→video, blog_post→blog_post, design_mockup→design, else other; status pending_review→in_review, revisions_requested→changes_requested, approved→approved, completed→published); `client_deliverable_interactions` → `deliverable_reviews` (latest of the four timestamps decides decision; read_at→viewed_at). `meetings`/`meeting_attendees` copy. `project_notes.type=standup` → `standups` (date = created_at in creator timezone; `is_late` = after 11:00 local); duplicates per day → keep first, others become comments on the project (issue).
- Verify: tasks count incl. subtasks; sum of time entries check; standups count.

### 4.6 comments
- `project_notes` (non-standup, non-kudos) → `comments`: subject = `noteable` (Task→task, Milestone→milestone, Deliverable→deliverable, Document→attachment(mapped document), User→user; NULL noteable → subject project); author = `creator_*` if set else `user_id` (user) else super-admin + issue; `type` general/note/comment→comment, meeting_minutes→meeting_minutes, daily_summary→note; `context` (JSON-in-varchar) → `anchor`; `parent_id` mapped; decrypt content with legacy key ("UNABLE TO READ" → issue). `kudos` type → `legacy_kudos_notes` archive. `comments` table: Conversation → thread comment kind note; Resource → archive. `invoice_comments`: action=comment → comment on invoice; other actions → activity_log entries on the invoice. `user_notes` → comment subject user (decrypt). `deliverable_comments` → comment subject deliverable, author contact, `context`→anchor. Wireframe annotations (noteable Wireframe) → archive.
- Verify: counts per source table.

### 4.7 attachments
- `files` → `attachments`: subject via morph map (Bill→bill, Email→message, ChatMessage→archive, Task→task, Project→project, ProjectExpendable→proposal|budget, Transaction→payment|ledger_entry, Invoice→invoice); `path` URL vs object → `disk=url|gcs`; `google_drive_file_id`→`disk=gdrive`; prefix `email-blocks/`→kind inline_image, purpose email_block; `expires_at` copy. `documents` handled in 4.4. `deliverables.attachment_path` → attachment on deliverable. Objects are **not** moved in R1 (same GCS bucket); `path` copied verbatim.

### 4.8 comms
- `email_templates` (+ `placeholder_definitions` via pivot) → `email_templates` with `placeholders` JSON (name, source from `source_model::source_attribute` mapped to registry keys; `is_dynamic/repeatable/link` → flags; unknown sources → `custom`). `email_apps` SMTP → `mailboxes(provider=smtp)`; API → archive. App Gmail → default mailbox.
- `conversations` → `threads`: `conversable` → contact via 4.3 map (NULL → contact NULL); `contractor_id`→owner; `project_id` copy; `subject`; `provider_thread_id` = first non-null `emails.gmail_thread_id`; ai_* copy.
- `emails` → `messages`: `type` received→inbound, sent→outbound (**but** rows with `type='sent'` and `sender_type` Client/Lead created before the 2025-07-22 backfill migration are inbound — apply legacy `inbox:fix-email-types` rule: direction = inbound if sender is contact); `status` map: draft→draft, saved→saved, pending→submitted, auto_send→approved, approved→sent(if sent_at) else approved, delayed→scheduled (scheduled_for from `schedules` row), sent→sent, received→received, pending_approval→pending_approval, pending_approval_received→screening, rejected/rejected_received→returned, unknown→screening (+thread project NULL); `body_format` per survey heuristics: NULL body + template → template; JSON object with greeting/paragraphs → **markdown** (render paragraphs; keep original in `headers.legacy_ai_body`); `draft_meta.body_format=markdown` → markdown; HTML-looking (`EmailHtml::looksLikeHtml`) → html (custom composer greeting prefix retained); `template_data.blocks` present → blocks; else text. `template_data` (double-decode with legacy `TemplateData::decode`) → `template_values` + `body_blocks` + `headers`. `to` → `message_recipients` (parse JSON array or comma list; if length==255 flag truncated issue). `sender_*` → author. `approved_by`, `sent_at`, `read_at`→`message_events(opened)`, `rfc_message_id`, `message_id`→provider_message_id, `gmail_thread_id`, `in_reply_to_email_id`, `is_private`, ai_status/ai_reason/ai_checked_at → `ai_check_status/ai_verdict`, `ai_draft*` → `message_drafts`. `deleted_at` copy. `body_text` derived (strip html/markdown). `rendered_html` NULL for legacy (preview re-renders from body).
- Rejections: for each legacy `rejected*` email create `approval_requests(kind send_email, status rejected, reason=rejection_reason, decided_by=approved_by?)`; for `pending_approval` create pending request.
- `user_interactions` email_open → `message_events`; `execution_logs` of AI approval steps (workflow 17) → `ai_reviews(kind outbound_check)` where `triggering_object_id` maps to a message (best effort).
- Thread `needs_reply_since` etc. recomputed by `inbox:audit-reply-clock --rebuild` after load.
- Verify: message counts by direction/status vs legacy distribution; every message has ≥1 recipient (issue otherwise).

### 4.9 finance
- `transaction_types` → `ledger_categories` (dedupe; `Initial Agreed Amount`, `Out of Scope` seeded). `crm_services` → catalogue. `project_services` → `project_services` + `service_milestones` from `payment_breakdown[]` (key = legacy milestone_key; label/amount; if breakdown missing → one milestone `full` = amount). `enquiry_*` → `enquiries`.
- `invoices` → `invoices` (number `OZI-{legacy id padded}`; `invoice_number` → `xero_number`; `status` draft/approved/sent/paid/partial_paid→partially_paid/void; `total_amount` kept, then recomputed from items — mismatch → issue not overwrite); `invoice_items` → items (`milestone_key` → service_milestone via map; missing → free-text item + issue; `line_total` computed); `xero_payment_service_ids` → pivot; `xero_invoice_id` → `xero_links`.
- `project_expendables` → `budgets` (user_id NULL; morph Project/Milestone) and `proposals` (user_id set; status `Pending Approval`→submitted, Shortlisted→shortlisted, Accepted→accepted, Rejected→rejected, Completed→completed; milestone from morph; `payment_terms` text → `payment_terms=[{label:'terms',text}]`).
- `bills` → `bills` (number `OZB-…`; status pending_approval→pending_approval, approved→approved, paid→paid, partial_paid→partially_paid, void→void; contractor→supplier; expendable→contract; `bill_payment_details` decrypt → `payout_snapshot` and also create/dedupe a `payout_methods` row for the supplier if none matches). `approval_flows/steps/instances/instance_steps` → `approval_flows` + `approval_requests(kind pay_bill, step=current_step_order, status)` (one request per instance; step history → activity_log).
- `transactions` → if `invoice_id` → `payments(direction in, payable invoice)`; if `bill_id` → `payments(direction out, payable bill)`; `type=bonus` → `legacy_bonus_transactions_from_transactions`; else `ledger_entries(kind income|expense)`. `currency` uppercased; `exchange_rate` → `fx_rate_to_base` when present else rate as_of payment_date from `exchange_rates` (USD-based legacy rates converted to base currency). `is_paid=false` on invoice/bill-linked rows → skip payment, record issue (unpaid "transaction" isn't a payment). Recompute `amount_paid` and statuses via `RecalculateInvoiceStatus`/`RecalculateBillStatus`.
- Xero/Stripe/Airwallex: `xero_connections`+`xero_tenants` → `xero_connections` rows (selected → active); `xero_payment_services`; `airwallex_xero_bank_mappings`; `stripe_configurations`→`stripe_apps`; subscriptions/payments (int minor units → decimal /100; `app_id` → FK); `stripe_payouts` → `bank_transactions(provider stripe)`; `currency_rates` → `exchange_rates(as_of = fetched_at date)`.
- Verify: Σ payments in per invoice = legacy paid amounts (sample); invoices/bills status distribution equals legacy after recompute (differences listed).

### 4.10 access & vault
- `magic_links`: type client → `access_links(kind client_dashboard, contact via email, token_hash)` (expired excluded), type external → `access_links(kind external_api)` (label, whitelist, max_uses, uses_count). `client_vault_credentials` → `vault_credentials` (public_id = legacy uuid; ciphertext columns copied verbatim — same VaultService scheme, same APP_KEY-independent PIN derivation: **confirm in D6-01 that decryption only needs PIN+salt; if APP_KEY is involved, re-encrypt**), shares copied. `otp_*`, `login_attempts`, `user_otps` → not migrated.

### 4.11 archive
`INSERT INTO legacy_x SELECT *, id AS legacy_id FROM legacy.x` for every table in 02 §09 plus `activity_log` (full) and `notifications` (unread only → v2 notifications for users, best-effort re-typed; rest archived).

### 4.12 verification & report
`legacy:verify` prints a table: step, legacy count, v2 count, issues by type, sample ids; must be attached to the sign-off. Spot checks (manual, 20 records each): a project page vs legacy, an inbox thread render vs legacy, an invoice with payments, a supplier proposal with bills.

## 5. Rehearsals & cutover
1. Rehearsal 1 on a fresh restore of legacy prod into `legacy_rehearsal` → run `all` → fix issues → rerun until issue count is understood and documented.
2. Rehearsal 2 (T-3 days) with timing; delta run tested (`--since`).
3. Cutover: announce freeze → stop legacy poll/scheduler and queue → put legacy in read-only → final `legacy:migrate all --since=<rehearsal2>` → `inbox:audit-reply-clock --rebuild`, `search:rebuild`, counters warm → set v2 mailbox `poll_cursor` = freeze time and start polling → switch URLs → smoke journeys → open. Rollback within 72h = switch URLs back; legacy DB untouched (any data created in v2 during that window is exported as a CSV report, not merged back).
